# 通用畫布與多畫板工作流

在原生設計工具、多畫板專案或共同編輯情境讀取。此頁定義操作原則，不定義任何平台 API、索引 schema、檔名副檔名或版本契約。

## 適配目前環境

| 能力 | 做法 |
|---|---|
| 能讀寫原生節點 | 使用實際的文件、頁面、畫板與節點 ID |
| 只能匯入 HTML／SVG | 先確認可保留的圖層、文字、元件與互動，再製作可匯入來源 |
| 只能上傳圖片 | 明確標記成品是點陣圖；另外保留可編輯來源 |
| 只能寫本地檔案 | 每個固定畫板用獨立來源檔，或依專案既有結構組織 |
| 無寫入能力 | 提供設計規格或原始碼，說明未寫入畫布 |

只有文件或工具明確提供時，才使用批次寫入、畫板索引、預覽大小、資產上傳與匯出功能。不要為通用工作流發明一套平台專用參數。

## 建立設計

1. **鎖定目標。** 使用者指定現有專案時，先讀取該專案；只有要求新建或目前確實沒有目標時才建立新的文件。
2. **讀取上下文。** 讀必要的畫板、品牌、Token、資產與元件，不把整個帳戶的專案都載入。
3. **定義畫板。** 每個畫板有穩定名稱、目的、尺寸與順序。固定海報使用明確寬高；網站頁面使用響應式容器。
4. **規劃布局。** 探索選項先用低保真草稿；畫板之間保留足夠空隙，名稱、註解及交付卡片不能互相遮擋。
5. **製作內容。** 用工具能保留的文字、圖形、圖片與元件；只有明確需要一張完整圖片時才扁平化。
6. **分批寫入。** 依工具實際容量與依賴順序批次操作。資產與被引用檔先到位，再建立引用；工具支援原子更新時可一併提交。
7. **渲染與交付。** 檢查目標尺寸、字型、溢出、互動及匯出結果，再提供實際可開啟的連結或檔案。

沒有「寫一檔必須立刻送一檔」的通則，也沒有略過目視檢查的通則；批次策略依工具限制與可驗證結果決定。

## 修改現有專案

1. 先定位使用者指定的畫板或節點，必要時讀 [view-state.md](view-state.md)。
2. 讀取最新內容與工具回報的版本／修改時間。保留不相關的頁面、圖層、註解、命名及未知 metadata。
3. 只修改任務範圍。新增、刪除或重排畫板時，才更新相應順序與引用。
4. 工具有版本前提、revision、ETag 或 compare-and-swap 時使用它，避免覆蓋他人編輯。
5. 遇到版本衝突，重讀受影響內容，重新套用最小修改；不要強制覆寫。連續衝突且無法安全合併時，保留修改方案並說明阻礙。
6. 完成後讀回必要節點或查看畫面，確認寫入落在正確目標；不能只以請求已送出作為完成證據。

## 資產與路徑

- 資產使用工具回傳的真實 ID／網址或專案內可解析的相對路徑，不猜測上傳端點。
- 只有環境要求上傳時才上傳；本地 HTML 可用本地資產，不強制改成遠端網址。
- 從文件取得的檔名與路徑先確認位於預定工作根目錄內。拒絕越界路徑，不將任意文字插入 shell 指令。
- 圖層可編輯、字體可編輯、元件可重用是不同能力，逐項確認，不以「可匯入」概括。
- 現有專案預設不重建、不改共享權限；交付網址使用工具實際回報的網址。

## 匯入、匯出與復查

HTML、SVG、PDF、PNG 的匯入效果依平台而異。SVG 可能保留圖形而改變字體，PDF 可能被拆成多段文字，PNG 只有像素；交付原生格式前應先確認轉換結果。

匯出失敗時，提供已完成的來源與實際錯誤，不宣稱已完成。衍生簡報、影片、文件的來源關聯見 [derived-deliverables.md](derived-deliverables.md)。
