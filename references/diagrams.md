# 通用圖解：節點、連線與可編輯性

在製作流程圖、組織圖、系統圖、泳道圖與時間軸前讀取。

## 選擇表示方式

| 需求 | 合適方式 |
|---|---|
| 可個別拖拉節點與連線 | 目標工具的原生圖形與連接器 |
| 精確固定布局且保留文字 | HTML 節點加 SVG 連線，或可編輯 SVG |
| 以文字維護流程與關係 | Mermaid 等環境已支援的圖解語法 |
| 單純展示或匯出 | 完整 SVG、PDF 或圖片，保留原始來源 |

編輯器把整張 SVG 當成一個物件時，不宣稱其內部可逐一拖拉；改用獨立圖形或另附原始碼。只有展示需求時可用一張完整 SVG，不需要逐段拆線。

## 先排節點

先列出每個節點的名稱、`left`、`top`、`width`、`height`，再算箭頭。HTML 固定圖解用一個 `position: relative` 容器，節點為絕對定位且 `box-sizing: border-box`。

- 同列共用中心 y，同欄共用中心 x。一般間距至少 48px；線路、標籤需要更大空間時，從 96px 起調整。
- 依最長標籤決定同類卡片尺寸。容器不夠時改布局或擴大畫板，不為塞入內容縮到難以閱讀。
- 中文字寬與英文字寬不同；估算只用於初排，最終以實際字型渲染確認。
- 決策菱形的文字維持正向；可用 SVG polygon 或工具原生形狀，不旋轉文字容器。
- HTML 背景與絕對定位子項不因 padding 自動留安全邊；座標要自行納入邊界。

## 連線計算

對節點 `(x, y, w, h)`：

| 邊 | 中點 |
|---|---|
| 左 | `(x, y + h/2)` |
| 右 | `(x + w, y + h/2)` |
| 上 | `(x + w/2, y)` |
| 下 | `(x + w/2, y + h)` |

箭頭從邊緣出發，箭頭尖端停在目標邊前約 1px。以箭頭尖端計算終點，避免 marker 超出節點；依 `refX`、`markerUnits` 與箭頭尺寸設定，不套用一個未驗證的縮短常數。

線路沿水平或垂直空隙通過，不穿越節點與文字。回圈走外側，預留至少約 48px 的路徑。雙向連線用不同接點，例如同一邊的 1/3 與 2/3 處。

一對多用主幹與分支，避免每條線都斜穿畫面。若工具原生連接器能跟隨節點，優先使用；手動座標線不會自動跟隨，移動節點後必須重算所有相關線。

## 圖層與標籤

順序為背景帶、連線、節點、標籤。箭頭文字獨立擺放，與線或節點至少約 8px；「是／否」靠近決策端，避免不知對應哪一條路。

多個 inline SVG 的 marker ID 應保持唯一，移除一條線不能破壞其他線。分段線只在末段加箭頭；虛線的箭頭頭部仍保持實心或清晰開口。

下例是標準 SVG 語法範例，不依賴編輯器執行階段。兩個節點的相向邊為 x=240 與 x=400，箭頭尖端停在 x=399：

```html
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 640 200" role="img" aria-labelledby="flow-title">
  <title id="flow-title">草稿送交審核</title>
  <defs>
    <marker id="flow-arrow-1" viewBox="0 0 8 8" refX="8" refY="4"
            markerWidth="8" markerHeight="8" markerUnits="userSpaceOnUse" orient="auto">
      <path d="M0 0 L8 4 L0 8 Z" fill="#334155"/>
    </marker>
  </defs>
  <path d="M240 100 H399" fill="none" stroke="#334155" stroke-width="2" marker-end="url(#flow-arrow-1)"/>
  <rect x="40" y="64" width="200" height="72" rx="8" fill="#f1f5f9" stroke="#64748b"/>
  <rect x="400" y="64" width="200" height="72" rx="8" fill="#f1f5f9" stroke="#64748b"/>
  <g fill="#0f172a" font-family="sans-serif" font-size="18" text-anchor="middle">
    <text x="140" y="106">草稿</text>
    <text x="500" y="106">審核</text>
  </g>
</svg>
```

## 驗收

檢查箭頭方向、每條分支與標籤、線是否穿越節點、文字換行、匯出後線寬與縮放清晰度。若要求可拖拉，實際確認節點能單獨選取，並確認移動後連線是否跟隨。拓樸與順序必須來自真實需求，不能為版面好看而增加步驟。
